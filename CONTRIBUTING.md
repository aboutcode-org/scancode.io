# Contributing to ScanCode.io

Thank you for your interest in contributing to AboutCode projects.
Please **read the following guidelines carefully before submitting a pull request**.

## Pull request rules

- **Start with an existing issue.** Ideas, questions, and implementation approaches
  are discussed in the issue, before writing any code. You do not need to ask to be
  assigned: present your approach in the issue. The PR comes next, with the code
  changes, and must link to the issue in its description.

- **Understand your code changes.** You must be able to explain them clearly. If
  you cannot walk a reviewer through your changes, the PR will not be accepted.

- **Disclose any AI usage.** Using AI tools is fine. Say which tools you used and
  for which parts. A PR fully generated by AI adds little: maintainers can run
  these tools themselves.

- **Include tests.** Any code change or addition must be accompanied by proper
  unit tests. Untested code will not be merged.

**Any PR that violates these rules will be closed.**

## Pull request title

Pull requests are squash merged: the PR title becomes the commit message on `main`.
It must follow the [Conventional Commits](https://www.conventionalcommits.org/)
format, `<type>(<optional scope>): <description>`.
For example: `feat: add the scan_package pipeline`.

## Pull request tips

To maximize your chances of a successful contribution:

- **Keep changes focused.** Address only what the issue requires. Do not bundle
  unrelated or structural changes, such as adding type hints.

- **Be patient.** Do not solicit maintainers for a review.

## Ways to contribute

See the [contributing documentation](https://scancodeio.readthedocs.io/en/latest/contributing.html)
for more ways to contribute.
